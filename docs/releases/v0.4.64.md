# Frame Control 0.4.64

Candidate notes for the merged changes since v0.4.62. This version is not yet published.

- Framey plugin controls retain their help text, tooltips, dropdown icons and native refs. Button, dropdown, text-field and progress controls honor their documented tab-navigation settings, and progress labels retain their counts.
- Plugin pages and notification actions retire callbacks when their view closes or is replaced. Managed-plugin metadata and ownership receipts have bounded reads and conservative installed-state reporting.
- The settings sample and author guide cover saved settings, panel reopen, reset, damaged-data refusal and native Decky restarts. Native AMD64/ARM64 and browser regression checks exercise persistence and clean shutdown.
- Managed AlarMe, MangoPeel, Bluetooth and Non-Steam Badges gain scoped lifecycle or child-IPC repairs. Notebook and PlayTime gain restart/persistence regression checks. These changes retain each plugin's documented compatibility limits.
- Release checks cover sample persistence, native plugin lifecycle and signed-package browser behavior on both Linux architectures. Terminal and Syncthing startup failures retain bounded diagnostics; managed Syncthing and official Terminal installation remain disabled.
- Maintainer tooling gains authenticated PostHog report intake, durable investigation history and Codex-based dispatch policy. Service deployment and credentials are configured separately.
- Linux Debian packages declare the desktop libraries the app needs, including GBM and the ALSA package alternative. AppImages select the supported static runtime and retain their existing sandbox launch setting.

## Verification limits

Publication requires green CI on the exact candidate commit, all tagged installer builds, an independent audit of downloaded installers and checksums, and a locked real Frame smoke test from the clean release checkout. The older rejected v0.4.63 tag and draft are preserved; they do not qualify this version.

Framey visibility in a worn headset, physical controller input, scrolling and the VR keyboard remain unverified. Native Linux containers, browser fixtures and synthetic input do not prove worn VR behavior or live-headset settings persistence. Audible alarms, real Bluetooth pairing, visible Steam-page badges, automatic PlayTime tracking and the real MangoHud overlay retain their documented unverified status. Historical ARM64 readiness/shutdown failures are preserved; passing later checks does not establish their cause or a repair.
