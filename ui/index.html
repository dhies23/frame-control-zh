无线适配器诊断

这台 Windows PC 的只读快照。无需连接头显即可使用。不会读取或改动 Frame 上的任何内容。

先点“读取 PC 适配器”开始。不会自动轮询。

改动适配器之前

存在多个 Microsoft Wi-Fi Direct Virtual Adapter 实例可能是正常的。诸如 #2 的编号、已断开的链路或未接入的设备，都不能确定哪个实例是多余的、可以安全禁用。此工具无法可靠识别 Steam 接收器的主用或活动实例，因此不提供禁用操作。

禁用错误的实例可能中断 Steam 串流、PC Wi-Fi、移动热点或无线显示。请保留完整的 PnP 实例 ID，并在断连前后对比快照交给 Steam 支持。不要仅凭这份列表禁用任何实例。

排查可能的 2.4 GHz 干扰

Razer 或其他 2.4 GHz 音频接收器可能与 Wi-Fi 共用频段。此清单无法测量干扰、检测音频接收器的信道，也无法证明掉线或 PC 关机的原因。

先短暂换用有线耳机对比。用延长线把 USB 无线接收器分开摆放；如果 PC 使用 2.4 GHz Wi-Fi，可对比有线网络或现有的 5/6 GHz 网络。每次只改一项并记录。这里不会改动任何网络或安全设置。

如果串流一开始就掉线

开始前先读取 PC 适配器，掉线后立即刷新。对比完整的 PnP 实例 ID、是否存在和问题代码；仅凭编号变化无法判断故障。同时记录 PC 自身的 Wi-Fi 是否也掉线。

如有条件，先用有线网络或有线音频重试一次，再把无线接收器分开摆放重试。每次只改一个条件。上面显示的 PC Wi-Fi 信道不是 Steam 接收器的信道，此检查也无法证明存在射频干扰。

如果适配器无法重新连接

停止失败的串流，关闭 Steam 的串流会话，并确认刷新后的 PC 快照里仍有该适配器。如果它不见了，在 PC 上重新插拔一次 USB 接收器后再读取；这会中断使用它的所有连接。

如果同一个 PnP 实例显示问题代码 22（已禁用），用 Windows 设备管理器查看该实例并执行启用。不要靠猜测去启用或禁用另一个编号的实例。如果它仍然缺失或报出其他问题代码，请保留前后 ID 和错误信息交给 Steam 支持。Frame Control 不会改动驱动、无线或网络设置。

备份 Frame

把游戏存档、设置和 Android 应用数据从头显复制到这台电脑上带日期的文件夹。 它只读取头显。游戏本体不会被复制：从 Steam 重新安装。

从不复制：Steam 登录文件 (steam.token、config.vdf、loginusers.vdf)、SSH 密钥、 钥匙环和其他密码。备份不会加密，游戏文件夹里可能存有启动器登录信息，请妥善保管。 先关闭 Android 应用：正在运行的应用会被跳过。

用 UEVR 在 VR 中游玩

praydog 的 UEVR 能把许多虚幻引擎游戏变成 VR 游戏。Frame Control 会下载 官方 UEVR 1.05 版本和 python.org 的 Windows Python，用来把 UEVR 加载进游戏 （约 20 MB），校验它们的哈希值，并将它们保存在该游戏的 Proton 前缀中，而不是游戏文件夹里。 移除会再将它们删除。

目前只在 Frame 上测试过一款游戏。游戏在 VR 中的画面和游玩效果会因游戏而异； 头显中 UEVR 自带的菜单里有各游戏的设置。
